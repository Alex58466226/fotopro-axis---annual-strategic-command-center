# 阶段 6 及后续工作计划

## 📋 阶段 6: 状态管理优化（可选）

### 目标
使用 Context API 统一管理全局状态，减少 props 传递，提升代码可维护性。

### 当前问题
- **状态分散**：App.tsx 中有 15+ 个 `useState`，状态管理分散
- **Props 传递过深**：很多组件需要传递多层 props
- **状态同步困难**：多个组件需要访问同一状态时，需要层层传递

### 解决方案

#### 6.1 创建 AppContext（应用全局状态）
**文件**: `contexts/AppContext.tsx`

**管理状态**:
- `strategies` - 策略树数据
- `tasks` - 任务列表
- `users` - 用户列表
- `auditLogs` - 审计日志
- `activeNodeId` - 当前选中的节点
- `filters` - 筛选条件

**提供方法**:
- `addStrategy()` - 添加策略
- `updateStrategy()` - 更新策略
- `deleteStrategy()` - 删除策略
- `addTask()` - 添加任务
- `updateTask()` - 更新任务
- `deleteTask()` - 删除任务
- `setActiveNode()` - 设置活动节点
- `setFilters()` - 设置筛选条件

#### 6.2 创建 AuthContext（认证状态）
**文件**: `contexts/AuthContext.tsx`

**管理状态**:
- `currentUser` - 当前登录用户
- `isAuthenticated` - 是否已登录
- `authMode` - 认证模式（login/register/forgot）

**提供方法**:
- `login()` - 登录
- `logout()` - 登出
- `register()` - 注册
- `resetPassword()` - 重置密码
- `setAuthMode()` - 切换认证模式

### 实施步骤

1. **创建 Context 文件** (1 天)
   - 创建 `contexts/AppContext.tsx`
   - 创建 `contexts/AuthContext.tsx`
   - 定义类型和接口

2. **迁移状态到 Context** (1 天)
   - 将 App.tsx 中的状态移到 Context
   - 更新 App.tsx 使用 Context
   - 确保功能正常

3. **更新组件使用 Context** (1 天)
   - 更新所有组件使用 Context 而不是 props
   - 减少 props 传递
   - 测试所有功能

### 预期收益

✅ **代码简化**
- App.tsx 进一步减少 200-300 行
- 组件 props 减少 50%+

✅ **可维护性提升**
- 状态集中管理，易于追踪
- 减少状态同步问题

✅ **性能优化**
- 避免不必要的 props 传递
- 可以更精确地控制组件重渲染

### 工作量评估
- **总工作量**: 2-3 天
- **风险**: 中等（需要仔细测试，避免功能回归）

### 是否必须？
❌ **不是必须的**，当前架构已经可以正常工作。阶段 6 是**优化项**，如果：
- 需要进一步提升代码质量
- 计划添加更多功能（状态管理会更复杂）
- 团队协作开发（统一状态管理更清晰）

## 💡 决策建议

### 是否做阶段 6？
**建议**: 如果计划添加更多功能（批量操作、搜索等），建议先做阶段 6，因为：
- 新功能会增加状态复杂度
- Context 可以更好地管理复杂状态
- 避免后续重构成本

**如果**: 只是维护现有功能，可以暂缓阶段 6。

### 下一步优先做什么？
**建议**: 先做**数据导入功能**，因为：
- 用户价值高（数据恢复）
- 与现有导出功能对应
- 相对独立，风险低
