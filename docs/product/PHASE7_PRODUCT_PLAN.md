# Phase 7: 产品功能增强计划

## 需求概述

用户提出三个新的开发需求：
1. **项目评估看板**：根据任务得分、事项拆分和时间效率作出项目评估
2. **拖拽功能**：实现拖拽交互
3. **视觉快速信息甄别**：通过视觉元素快速识别信息

---

## 一、项目评估看板

### Context

**业务目标**：
- 为项目管理者提供数据驱动的决策支持
- 快速识别项目健康度、执行效率和风险点
- 支持多维度评估（任务质量、进度、时间效率）

**目标用户**：
- 项目经理、团队负责人
- 需要快速了解项目整体状况的决策者

**成功指标**：
- 用户能在 30 秒内了解项目整体状况
- 关键指标一目了然，无需深入数据
- 支持导出评估报告

### 澄清问题

**Q1: 评估看板的展示位置？**
- 选项 A：独立的新页面/标签页
- 选项 B：在现有页面中新增一个可折叠的看板区域
- 选项 C：在 Header 中显示关键指标卡片（当前已有部分）

**Q2: 评估看板的数据范围？**
- 选项 A：当前选中的策略分支（L1 及其所有子策略和任务）
- 选项 B：全局所有数据
- 选项 C：支持切换范围（当前分支/全局）

**Q3: 时间效率如何计算？**
- 选项 A：计划时间 vs 实际时间（需要记录实际完成时间）
- 选项 B：任务完成率（已完成任务数 / 总任务数）
- 选项 C：平均任务周期（从开始到完成的天数）

**Q4: 事项拆分如何量化？**
- 选项 A：策略层级深度（L1-L3 的层级数）
- 选项 B：任务数量分布（每个策略下的任务数）
- 选项 C：任务粒度评估（任务平均时长、复杂度）

### 产品方案（基于假设）

**假设**：
- 展示位置：在 Header 区域新增一个"项目评估"按钮，点击后打开全屏模态框
- 数据范围：当前选中的策略分支（L1）
- 时间效率：基于任务完成率和平均进度
- 事项拆分：基于任务数量分布和层级结构

#### 功能设计

**1. 评估看板入口**
- 位置：Header 右侧，与"智能周报"按钮并列
- 图标：📊 或 📈
- 文字："项目评估"

**2. 看板内容结构**

```
┌─────────────────────────────────────────┐
│  项目评估看板 - [当前策略名称]          │
├─────────────────────────────────────────┤
│                                         │
│  【核心指标卡片区】                      │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐  │
│  │ 任务 │ │ 平均 │ │ 时间 │ │ 事项 │  │
│  │ 得分 │ │ 进度 │ │ 效率 │ │ 拆分 │  │
│  │ 85   │ │ 72%  │ │ 88%  │ │ 良好 │  │
│  └──────┘ └──────┘ └──────┘ └──────┘  │
│                                         │
│  【详细分析区】                          │
│  ├─ 任务得分分布（柱状图/饼图）          │
│  ├─ 时间效率趋势（折线图）                │
│  ├─ 事项拆分结构（树状图）                │
│  └─ 风险任务列表（低分/延期任务）         │
│                                         │
│  【操作区】                              │
│  [导出报告] [刷新数据] [关闭]             │
└─────────────────────────────────────────┘
```

**3. 核心指标计算**

**任务得分（Task Score）**：
- 计算公式：`平均得分 = Σ(任务得分) / 已评分任务数`
- 显示：数值 + 颜色编码（绿色：≥80，黄色：60-79，红色：<60）
- 数据来源：`tasks.filter(t => t.score !== undefined).map(t => t.score)`

**平均进度（Average Progress）**：
- 计算公式：`平均进度 = Σ(任务进度) / 任务总数`
- 显示：百分比 + 进度条
- 数据来源：`tasks.map(t => t.progress)`

**时间效率（Time Efficiency）**：
- 计算公式：`时间效率 = 已完成任务数 / 总任务数 × 100%`
- 或：`时间效率 = 平均进度 / 时间进度（已过时间 / 总时间）`
- 显示：百分比 + 效率等级（优秀/良好/需改进）
- 数据来源：`tasks` 的 `status` 和 `progress`

**事项拆分（Task Breakdown）**：
- 评估维度：
  - 任务数量分布（每个 L3 策略下的任务数）
  - 任务粒度（任务平均时长）
  - 层级结构完整性（是否有 L2/L3 缺失）
- 显示：文字描述 + 可视化图表
- 数据来源：`strategies` 和 `tasks` 的层级关系

**4. 详细分析图表**

**任务得分分布**：
- 类型：柱状图或饼图
- X 轴：得分区间（0-20, 21-40, 41-60, 61-80, 81-100）
- Y 轴：任务数量
- 颜色：绿色（高）、黄色（中）、红色（低）

**时间效率趋势**：
- 类型：折线图
- X 轴：时间（按周或月）
- Y 轴：效率百分比
- 数据点：每周/每月的平均效率

**事项拆分结构**：
- 类型：树状图或桑基图
- 显示：L1 → L2 → L3 → 任务数量的层级关系
- 颜色：不同层级使用不同颜色

**风险任务列表**：
- 筛选条件：
  - 得分 < 60 的任务
  - 进度 < 50% 且已过计划时间 50% 的任务
  - 状态为 "in_progress" 但长时间未更新的任务
- 显示：任务名称、负责人、得分、进度、风险原因

**5. 导出功能**
- 格式：PDF 或 HTML
- 内容：核心指标 + 详细分析图表 + 风险任务列表
- 文件名：`项目评估报告_[策略名称]_[日期].pdf`

### 技术可行性

**数据来源**：
- ✅ 任务得分：`Task.score`（已存在）
- ✅ 任务进度：`Task.progress`（已存在）
- ✅ 任务状态：`Task.status`（已存在）
- ✅ 时间信息：`Task.start`、`Task.end`（已存在）
- ✅ 层级关系：`StrategyNode.level`、`Task.parentId`、`Task.rootId`（已存在）

**图表库选择**：
- 选项 A：**Recharts**（推荐）
  - 优点：React 原生，轻量，易用
  - 缺点：功能相对基础
- 选项 B：**Chart.js + react-chartjs-2**
  - 优点：功能强大，图表类型丰富
  - 缺点：体积较大
- 选项 C：**D3.js**
  - 优点：最灵活，可定制性强
  - 缺点：学习曲线陡，开发时间长

**推荐**：使用 **Recharts**，满足需求且开发效率高。

**实施复杂度**：
- 数据计算：低（已有数据，只需聚合）
- UI 组件：中（需要创建新的模态框组件）
- 图表集成：中（需要引入图表库）
- 导出功能：中（需要 PDF 生成库）

**工作量评估**：3-5 天

### 风险

**用户价值风险**：
- 如果指标计算不准确，可能误导决策
- 如果看板信息过载，用户可能无法快速理解

**技术风险**：
- 图表库可能增加构建体积
- 大量数据计算可能影响性能

**缓解措施**：
- 提供指标计算说明，让用户理解数据含义
- 使用 `useMemo` 缓存计算结果
- 考虑虚拟化或分页加载大量数据

## 二、拖拽功能

### Context

**业务目标**：
- 提升用户操作效率
- 支持直观的任务排序和调整
- 改善用户体验

**目标用户**：
- 所有用户
- 需要频繁调整任务顺序的用户

**成功指标**：
- 用户能通过拖拽快速调整任务顺序
- 拖拽操作流畅，无卡顿
- 拖拽后数据正确保存

### 澄清问题

**Q1: 拖拽的应用场景？**
- 选项 A：任务列表中的任务排序
- 选项 B：甘特图中的任务时间调整（拖拽改变开始/结束时间）
- 选项 C：策略树中的策略顺序调整
- 选项 D：以上全部

**Q2: 拖拽后的数据保存？**
- 选项 A：立即保存到 Supabase
- 选项 B：批量保存（拖拽完成后统一保存）
- 选项 C：用户手动保存

**Q3: 拖拽的优先级？**
- 选项 A：任务列表排序（高优先级）
- 选项 B：甘特图时间调整（中优先级）
- 选项 C：策略树排序（低优先级）

### 产品方案（基于假设）

**假设**：
- 应用场景：任务列表排序 + 甘特图时间调整
- 数据保存：拖拽完成后立即保存（防抖 500ms）
- 优先级：先实现任务列表排序

#### 功能设计

**1. 任务列表拖拽排序**

**交互设计**：
- 拖拽手柄：任务项左侧显示拖拽图标（⋮⋮）
- 拖拽反馈：拖拽时显示半透明预览，目标位置显示插入线
- 拖拽限制：只能在当前筛选结果内排序

**数据模型**：
- 在 `Task` 接口中添加 `order?: number` 字段
- 排序逻辑：按 `order` 字段排序，如果 `order` 相同则按 `start` 日期排序

**保存逻辑**：
- 拖拽完成后，重新计算所有任务的 `order` 值
- 使用防抖（500ms）批量保存到 Supabase

**2. 甘特图拖拽时间调整**

**交互设计**：
- 拖拽任务条：可以左右拖拽改变任务的开始时间
- 拖拽任务条边缘：可以调整任务的结束时间
- 拖拽反馈：实时显示新的开始/结束日期

**数据保存**：
- 拖拽完成后，更新任务的 `start` 和 `end` 字段
- 立即保存到 Supabase

**3. 策略树拖拽排序（可选）**

**交互设计**：
- 拖拽策略节点：可以调整同层级策略的顺序
- 拖拽到其他策略：可以改变策略的父级（需要验证层级规则）

**数据模型**：
- 在 `StrategyNode` 接口中添加 `order?: number` 字段

### 技术可行性

**拖拽库选择**：
- 选项 A：**@dnd-kit/core**（推荐）
  - 优点：现代、轻量、TypeScript 支持好，无障碍支持
  - 缺点：相对较新，社区较小
- 选项 B：**react-beautiful-dnd**
  - 优点：成熟、文档完善、社区大
  - 缺点：不再维护，可能有兼容性问题
- 选项 C：**react-dnd**
  - 优点：功能强大，支持复杂拖拽场景
  - 缺点：学习曲线陡，配置复杂

**推荐**：使用 **@dnd-kit/core**，现代且维护良好。

**实施复杂度**：
- 任务列表拖拽：中（需要处理排序逻辑和数据保存）
- 甘特图拖拽：中高（需要处理时间计算和视觉反馈）
- 策略树拖拽：高（需要处理层级验证）

**工作量评估**：
- 任务列表拖拽：2-3 天
- 甘特图拖拽：3-4 天
- 策略树拖拽：2-3 天
- **总计**：7-10 天（如果全部实现）

### 风险

**用户体验风险**：
- 拖拽操作可能误触发（特别是在移动设备上）
- 拖拽后数据丢失（如果保存失败）

**技术风险**：
- 拖拽库可能与现有组件冲突
- 大量数据拖拽可能影响性能

**缓解措施**：
- 提供明确的拖拽手柄，避免误触发
- 添加拖拽操作的撤销功能
- 使用防抖减少保存请求
- 添加拖拽操作的错误提示

## 三、视觉快速信息甄别

### Context

**业务目标**：
- 帮助用户快速识别任务状态、优先级、风险等信息
- 减少用户认知负担
- 提升信息浏览效率

**目标用户**：
- 所有用户
- 需要快速浏览大量任务的用户

**成功指标**：
- 用户能在 1 秒内识别任务的关键信息
- 视觉编码清晰，不会产生歧义
- 支持色盲用户（使用图标辅助）

### 澄清问题

**Q1: 需要快速识别的信息类型？**
- 选项 A：任务状态（todo/in_progress/completed/confirmed）
- 选项 B：任务优先级（P0/P1/P2）
- 选项 C：任务得分（高分/中分/低分）
- 选项 D：任务风险（延期/低分/无进展）
- 选项 E：以上全部

**Q2: 视觉编码方式？**
- 选项 A：颜色编码（背景色/边框色）
- 选项 B：图标编码（状态图标/优先级图标）
- 选项 C：标签/徽章（文字标签）
- 选项 D：组合使用（颜色 + 图标 + 标签）

**Q3: 应用位置？**
- 选项 A：任务列表
- 选项 B：甘特图
- 选项 C：策略树
- 选项 D：以上全部

### 产品方案（基于假设）

**假设**：
- 信息类型：任务状态 + 优先级 + 得分 + 风险
- 编码方式：颜色 + 图标 + 标签组合
- 应用位置：任务列表 + 甘特图

#### 功能设计

**1. 任务状态颜色编码**

```
todo (待办)        → 灰色背景 (#F5F5F5)
in_progress (进行中) → 蓝色背景 (#E3F2FD)
completed (已完成)  → 绿色背景 (#E8F5E9)
confirmed (已确认)  → 深绿色背景 (#C8E6C9)
```

**2. 优先级图标编码**

```
P0 (紧急) → 🔴 红色圆点 + "P0" 标签
P1 (重要) → 🟡 黄色圆点 + "P1" 标签
P2 (普通) → ⚪ 灰色圆点 + "P2" 标签
```

**3. 得分颜色编码**

```
高分 (≥80) → 绿色边框 + ✓ 图标
中分 (60-79) → 黄色边框 + ⚠ 图标
低分 (<60) → 红色边框 + ✗ 图标
未评分 → 无边框
```

**4. 风险标识**

```
延期风险 → 红色闪烁边框 + ⚠ 图标
低分风险 → 红色边框 + 低分标识
无进展风险 → 黄色边框 + 时钟图标
```

**5. 任务列表视觉增强**

**任务项结构**：
```
┌─────────────────────────────────────────┐
│ [🔴P0] [状态图标] 任务名称              │
│         [得分徽章] [风险标识]           │
│         负责人 | 渠道 | 产品            │
└─────────────────────────────────────────┘
```

**6. 甘特图视觉增强**

- 任务条颜色：根据状态和优先级组合
- 任务条边框：根据得分和风险
- 任务条图标：在任务条上显示优先级图标

**7. 筛选器视觉增强**

- 在筛选面板中，使用颜色和图标标识当前筛选条件
- 筛选结果数量用徽章显示

### 技术可行性

**实施复杂度**：
- 颜色编码：低（只需修改 CSS）
- 图标编码：低（已有 Icon 组件）
- 标签/徽章：低（使用 Tailwind CSS 样式）
- 组合使用：中（需要设计统一的视觉系统）

**工作量评估**：2-3 天

### 风险

**用户体验风险**：
- 颜色过多可能导致视觉混乱
- 色盲用户可能无法识别颜色编码

**技术风险**：
- 视觉样式可能与现有设计冲突
- 需要确保视觉编码的一致性

**缓解措施**：
- 使用图标辅助颜色编码
- 提供视觉编码说明文档
- 遵循 Notion 风格，保持设计一致性
- 考虑添加"高对比度"模式
